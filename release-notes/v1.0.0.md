# walq 1.0.0

Both `@walq/core` and `@walq/better-sqlite3` are released at 1.0.0.

## Breaking changes

- Move handler-failure retry backoff from the `retry` wrapper to the top-level `backoff` queue option. Update callers that configure retry backoff.
- Custom storage adapters must implement the new storage operations required by job counts, durable pause/resume, and other queue features. Consult the [storage contract](https://github.com/unsady/walq/blob/main/docs/storage-contract.md) before upgrading an adapter.
- Upgrade both packages together: `@walq/better-sqlite3` now requires `@walq/core` 1.x.

## Highlights

- Process leased jobs in batches with `queue.processMany()`.
- Prioritize jobs, deduplicate by queue-scoped keys, and enforce persistent concurrency limits for job groups. Eligible groups and ungrouped jobs share round-robin claims.
- Pause and resume queues durably; inspect persisted job counts with `queue.stats()`.
- Register durable repeating schedules with intervals or UTC cron expressions.

## SQLite migration

Opening an existing database automatically migrates supported schemas v2–v10 to v12; schema v11 is not supported. Stop workers and back up the database before upgrading. Existing pre-v6 jobs receive a deterministic approximate historical insertion order (by creation time, then ID). New databases and migrations from v10 or earlier do not retain the obsolete `walq_active_group` index; if your database was created by an earlier v12 implementation, stop workers and run `DROP INDEX IF EXISTS walq_active_group` to remove it.
