# Storage contract

`Storage` is exported from `@walq/core/storage`; its types are defined in [`packages/core/src/storage.ts`](../packages/core/src/storage.ts). This contract specifies the behavior adapters must preserve.

## Shared rules

- Queue matching is exact. Every read, mutation, claim, and cleanup is scoped to the requested queue; queue names share no job state.
- Timestamps are nonnegative safe-integer Unix milliseconds; lease durations, attempts, and limits are positive safe integers. Retention bounds are `null` or nonnegative safe integers. Computed expiries must remain safe. The caller supplies `now`; adapters do not establish a shared clock. Distributed callers need synchronized clocks.
- Names are nonempty strings; data is serialized JSON. Invalid inputs reject without mutation. Error classes and messages are unspecified.
- Persist mutations before resolving. Invalid input and storage/transport errors reject; they are not `false` or `lease_lost`. A transport error may leave commit status uncertain, so enqueue is not idempotent.
- IDs and lease tokens are opaque. Generate unique IDs and a fresh token per successful claim. Delivery is at-least-once: tokens protect queue state, not handler side effects.

## Operations

- **`enqueue(input)`** creates an independent pending job with a generated ID, `createdAt = now`, `attemptsMade = 0`, and `error = null`. `availableAt` may be in the past. Matching data or names do not deduplicate.
- **`enqueueMany(inputs)`** follows `enqueue` in input order. Validate all inputs before mutation; commit all inserts atomically or none. Empty input returns `[]`.
- **`claim(input)`** atomically recovers expired leases for that queue and claims up to `limit` due jobs. Expiry is `expiresAt <= now`; recover all expired jobs even when no job is returned or the limit is reached. With attempts remaining, recovery returns a job to pending at its old expiry; otherwise it marks it failed. It preserves the last error and invalidates the old token, without overwriting a concurrent heartbeat or completion. Expiry alone does not change stored state.
  - Claim only pending jobs with `availableAt <= now` and `attemptsMade < attempts`, ordered by `availableAt`, then binary ID. Increment `attemptsMade` and assign a fresh token with `expiresAt = now + leaseDuration` atomically. Each claim is atomic; strict FIFO across workers is not guaranteed. An attempt counts a claim, including one whose handler never starts; `attempts` includes the initial claim.
- **`claimQueues?(requests)`** is optional; results correspond to requests in order, and each request has standalone `claim` semantics. Validate all requests before mutation. Requests for the same queue see earlier changes. An adapter may commit the group together or independently; callers must not assume cross-request atomicity. Empty input returns `[]`.
- **`inspect` / `list`** return queue-scoped snapshots; `inspect` returns `null` for an absent ID or one in another queue. `list` requires one of `pending`, `active`, `completed`, `failed`, or `cancelled`. Its order is deterministic: pending by availability ascending, active by expiry ascending, terminal statuses by finish time descending; binary ID breaks ties. Reads are not reservations. Expired active jobs stay active until claimed for recovery. Snapshots never expose lease credentials.
- **`retry`** accepts failed jobs only, makes them pending at `now`, clears `finishedAt`, and preserves `attemptsMade` and error. If exhausted, set `attempts = attemptsMade + 1` to grant one more claim; reject on safe-integer overflow.
- **`cancel`** accepts pending jobs only and records a terminal `cancelled` state. **`reschedule`** changes availability of pending jobs only; past times are valid. **`remove`** physically deletes any job except active ones, even if an active lease has expired but is not yet recovered.
- Retry, cancel, reschedule, and remove return `false` for a missing job, another queue, or an incompatible state; otherwise `true`. Invalid input and storage errors reject.
- **`complete`, `fail`, `heartbeat`** require an active job, the current token, and `expiresAt > now`. Return `lease_lost` without mutation otherwise; storage errors reject. Completion marks the job completed and invalidates its lease. Failure records its error and returns the job to pending at `retryAt` only if non-null and attempts remain; `retryAt <= now` is valid. Otherwise it marks the job failed. `applied` means the mutation was recorded, not that failure was retried. Heartbeat retains the token and sets expiry to `max(current expiry, now + leaseDuration)`; it cannot revive an expired lease.
- **`cleanup`** atomically deletes up to `limit` completed or failed jobs from the requested queue; pending, active, and cancelled jobs are excluded. Per status, `count` keeps the newest N and `maxAge` removes rows with `finishedAt < now - maxAge`; a row is eligible if it exceeds either bound. `null` disables a bound; two null bounds keep all rows. Delete oldest eligible rows first, ordered by finish time then binary ID. Return `{ removed, more }`, where `more` may conservatively be true; repeated bounded calls must converge and remain restart-safe. Work must depend on the batch limit and retention bounds, not total history.

For terminal jobs, set `finishedAt` to the operation's `now`; pending and active jobs have `finishedAt = null`. Completion preserves attempt history and the last error; failure and expiration recovery do not increment attempts. Cancelled jobs are not covered by automatic retention.
